# MASTER DEVELOPMENT PROMPT — SIGILWEAVER

이 문서는 이전 대화 없이 이 문서만 읽고 프로젝트 전체를 개발할 수 있도록 작성된 독립 개발 문서다.
Game Design Document + Technical Design Document + Development Roadmap + AI Coding Instructions를 겸한다.

---

## 0. 너의 역할

너는 이 프로젝트의 **시니어 게임 프로그래머이자 테크니컬 디렉터**다. 단순 코드 생성기가 아니다.
기존 코드를 읽고, 구조를 파악하고, 작은 단위로 구현하고, 매 단계 빌드와 테스트를 확인하고, 오류의 원인을 분석한 뒤 고친다.
이 문서에 정의된 게임의 정체성을 지키는 범위 안에서 충분한 자율성을 가진다(§16 참조).

## 1. 프로젝트 목표

**SIGILWEAVER** — 스마트폰을 세워두고, 전면 카메라 앞에서 실제 손으로 고대 인장(Sigil)을 맺어 마법을 시전하는 모바일 로그라이트 아레나 디펜스.

한 문장 설명:
> "손으로 마법 문자를 그려 싸우는, 카메라 기반 로그라이트."

목표 수준: 기술 데모가 아니라 **출시 가능한 완성작이자 포트폴리오 대표작**.
증명하려는 역량: 실시간 Computer Vision 입력 시스템, 데이터 기반 Spell/Effect 아키텍처, 모바일 최적화, 인터랙션 디자인.

## 2. 핵심 디자인 철학 (모든 결정의 판단 기준)

1. **제스처가 게임의 전부다.** 이동 조작은 없다. 폰은 거치하고, 양손 중 한 손(또는 원하면 양손 교대)으로 인장을 맺는 것이 유일한 전투 입력이다. "제스처를 버튼으로 바꾸면 재미가 사라져야 한다."
2. **인식 오류는 플레이어 잘못이 아니다.** 게임 디자인이 인식 지연·오류를 흡수한다: 상태 기반 포즈 입력, 넉넉한 텔레그래프, 항상 보이는 인식 피드백.
3. **콘텐츠 양이 아니라 시스템으로 재미를 만든다.** Trigger/Condition/Action/Modifier 조합에서 창발하는 시너지가 반복 플레이의 이유다.
4. **강화는 숫자만 키우지 않는다.** 룬은 마법의 행동을 바꾸고, 일부 룬은 제스처 문법 자체를 바꾼다.
5. **"작동한다" ≠ "게임처럼 느껴진다."** 폴리싱(타격감, 피드백, 사운드)은 부차 작업이 아니라 각 Phase의 완료 조건이다.
6. **MVP → Vertical Slice → Alpha → Beta → Release.** 처음부터 AAA 구조를 만들지 않는다. 과도한 추상화 금지.

## 3. 플레이어 경험과 자세

- 기본 자세: 폰을 책상/거치대에 **세로로 거치**, 플레이어는 40~80cm 거리에 앉음. 전면 카메라 사용.
- 한 손으로 인장을 맺는다(왼손/오른손 모두 동일하게 동작해야 함 — 좌우 미러 정규화 필수).
- 한 런 10~15분. 팔을 계속 들 필요 없도록, 웨이브 사이에는 손을 내릴 수 있는 휴지 구간이 있다.
- 세로 화면. 상단 2/3 = 전장, 하단 1/3 = 손 인식 피드백 영역(카메라 프리뷰 실루엣 + 인식 상태).

## 4. Core Loop / Combat Loop

**Core Loop (런 구조):**
전투 웨이브 방 → 룬 3택1 보상 → 전투 → 이벤트 방(택1 선택지) → 엘리트 → 전투 → 보스 → 클리어/사망 → 문자 파편(메타 재화) 획득 → 메타 성장 → 새 런.
한 런 = 방 8~10개, 10~15분.

**Combat Loop (초 단위):**
적 스폰(텔레그래프 포함) → 플레이어가 위협을 읽음 → 어떤 인장/인장문을 쓸지 판단 → 손으로 인장을 맺음 → 마법 발동 → 시너지 연쇄 → 위협 제거 or 피격 → 다음 위협.
적의 모든 공격은 **1.5~3.0초의 명확한 텔레그래프**를 가진다(인식 지연 흡수 장치).

## 5. Sigil System (기본 인장 5종)

| 인장 | 손 모양 | 마법 | 역할 |
|---|---|---|---|
| **Bolt** ☝ | 검지만 폄 | 조준선 방향 단일 투사체 | 기본 딜, 빠른 쿨다운 |
| **Ward** ✊ | 주먹 | 0.8초 전방위 방어막 | 방어/회피 대체, 타이밍 스킬 |
| **Pulse** 🖐 | 손바닥 완전히 폄 | 전방위 넉백 파동 | 군중 제어, 근접 위기 탈출 |
| **Arc** ✌ | 검지+중지 V | 가장 가까운 적에게 번개 | 유도 딜, 마나 소모 |
| **Focus** 🤏 | 엄지+검지 핀치 유지 | 채널링: 마나 회복 | 리스크 감수(무방비) ↔ 자원 회복 |

- 조준: 기본은 자동 조준(가장 가까운/위협적인 적). 손목 위치의 좌우 이동으로 조준 보정 가능(선택적 고급 조작, MVP 이후).
- 각 인장은 **인식 확정 즉시 발동**한다. 대기 시간 없음.

## 6. Sigil Phrase System (인장문 = 시퀀스 캐스팅)

- 발동한 인장은 발동과 동시에 **토큰 버퍼**에 쌓인다. 버퍼가 등록된 인장문과 일치하는 순간 인장문 마법이 **추가로** 발동되고 버퍼가 비워진다.
- 이 규칙 덕분에: 단일 인장은 항상 즉시 나가고(오인식에도 무언가는 발동), 인장문은 "연계 보너스"로 자연스럽게 얹힌다. 별도의 시전 확정 대기가 없다.
- 토큰 간 최대 간격 2.5초. 초과 시 버퍼 리셋. 인장문 길이는 2~3토큰.
- 인장문은 마나를 소모한다(단일 인장 중 Arc만 소량 소모, 나머지는 쿨다운만).

**Vertical Slice 기준 인장문 3종 (초기값, 밸런싱 대상):**
1. ✊ → ✌ → 🖐 = **Thunderstorm**: 3초간 화면 전역 낙뢰
2. 🖐 → ✊ → ☝ = **Fire Lance**: 관통 대형 화창 + 화상
3. ✌ → ✌ = **Chain Surge**: 즉시 3연쇄 번개 (짧고 싼 입문용 인장문)

Release까지 8종 이상으로 확장. 인장문은 처음부터 다 주지 않고 메타 진행으로 "복원"한다(§10).

## 7. Rune / Upgrade / Synergy System

**모든 룬은 데이터(JSON)로 정의하며 Trigger–Condition–Action–Modifier 구조를 따른다.**

```jsonc
// data/runes/burning-touch.json (예시)
{
  "id": "burning_touch",
  "name": "타오르는 인장",
  "rarity": "common",
  "hooks": [{
    "trigger": "onSpellHit",           // 이벤트 버스의 이벤트명
    "condition": { "spellTag": "fire" },
    "action": { "type": "applyStatus", "status": "burn", "duration": 3, "dps": 4 }
  }]
}
```

룬의 세 계열:
1. **행동 변형 룬**: 투사체 관통/분열/폭발/튕김/귀환, 처치 시 투사체 생성, 화상 적 사망 시 폭발 등. 수치 +10% 류의 룬은 전체의 30% 이하로 제한한다.
2. **문법 룬 (핵심 차별점)**: 제스처 시스템 자체를 성장시킨다.
   - "굳은 결의": Ward가 반격 Ward로 변화(막은 공격을 투사체로 반사)
   - "유창한 손": 인장 안정화 요구 프레임 4→3 (신체 입력이 빨라짐)
   - "메아리 인장": 같은 인장을 2초 내 2회 맺으면 두 번째는 강화 발동
   - "연장된 문장": 인장문 토큰 간격 2.5→4.0초
   - "개화": Arc → Chain Arc (3연쇄)
3. **자원/체질 룬**: 최대 마나, Focus 회복량, 체력 등.

시너지 설계 원칙: 상태이상(화상/감전/빙결) × 트리거(적 사망/피격/방어 성공) × 생성(투사체/폭발/장판)이 서로의 입력이 되도록 한다. 예: 화상 → 화상 적 사망 시 폭발 → 폭발이 감전 부여 → 감전 적에게 Arc 데미지 2배.

## 8. Enemy / Boss Design (Vertical Slice 기준)

- **Crawler**: 다수 직진 근접. 물량으로 Pulse/광역 인장문을 강요.
- **Lobber**: 원거리 곡사 투척. 착탄 지점 텔레그래프 표시, Ward 타이밍 연습 대상.
- **Shellback**: 전면 방패. 넉백(Pulse)으로 자세를 무너뜨린 뒤에만 피해가 들어감 → 인장 조합 강요.
- **Boss — 침묵의 서기관(The Mute Scribe)**: 3페이즈. 주기적으로 화면에 고대 문자를 띄우며 "봉인 문장"을 시전하는데, 플레이어가 제한 시간 내 **지정된 인장문을 맺으면 봉인을 파훼**하고 대미지 배수 윈도우가 열린다. 보스전 자체가 제스처 숙련도 시험이 되도록.

Release까지 적 12종+, 보스 3종(각 챕터당 1). 모든 적 스탯/패턴 파라미터는 데이터 파일로.

## 9. Stage / Run Structure

- 챕터 = 방 8~10개의 시퀀스. 방 종류: 전투 / 엘리트 / 이벤트(선택지) / 보스.
- Vertical Slice: 챕터 1개. Release: 챕터 3개(새 적 조합 + 새 기믹, 예: 어둠 챕터는 인식 피드백 UI가 약해지는 대신 보상 증가 — 신중히 테스트 후 결정).
- 난이도 곡선: 웨이브 내 스폰 예산(budget) 시스템으로 데이터 기반 제어.

## 10. Meta Progression

- 런 종료 시 **문자 파편(Glyph Shards)** 획득 (진행도 비례).
- 파편으로 해금: 새 인장문 "복원", 시작 축복(시작 룬 1개 선택권), 시작 마나/체력 소폭, 룬 풀에 새 룬 추가.
- 원칙: 메타 성장은 "선택지 확장" 위주. 순수 스탯 인플레는 최소화하여 실력 게임의 정체성 유지.

## 11. World / Lore

말이 힘을 잃은 세계. 옛 마법사들은 목소리로 주문을 외웠으나 '침묵'이 내린 뒤 언어 마법은 사라졌고, 손으로 문자를 그리는 인장술만이 남았다. 플레이어는 마지막 인장술사(Sigilweaver)로서, 침묵의 근원으로 향하며 런마다 잊힌 인장문을 하나씩 복원한다. 메타 진행(인장문 복원)이 곧 서사다. 대사는 최소화하고 환경과 UI 텍스트로 전달한다.

## 12. UX / UI / Accessibility

**인식 피드백 (항상 표시, 최우선 UI):**
- 하단 손 실루엣: 카메라에 손이 잡히는지, 어떤 인장으로 인식 중인지 실시간 표시.
- 인식 게이지: 포즈 안정화 진행도(N프레임 검증 진행률)를 링으로 표시 → "거의 됐다"가 보이게.
- 인장 확정 순간: 화면 플래시 + 인장 문자 이펙트 + 사운드 + 햅틱. 실패/버퍼 리셋도 명확한(그러나 처벌적이지 않은) 피드백.
- 토큰 버퍼 표시: 현재까지 맺은 인장열과 매칭 가능한 인장문 힌트.

**온보딩:**
- 첫 실행: 카메라 권한 설명 → 조명/거리 캘리브레이션(손을 원 안에, 5개 인장 각 1회 성공) → 튜토리얼 전투.
- 캘리브레이션 결과(인식 임계값 보정치)는 저장.

**접근성 / 실패 대비:**
- 설정에서 안정화 프레임 수, 인장문 간격을 조절 가능("여유로운 손" 모드).
- **보조 입력 모드**: 카메라 사용 불가 시 화면 하단 인장 버튼 5개로 플레이 가능. 이 모드는 개발 중 디버그 입력과 코드를 공유한다(GestureSource 추상화, §14). 단, 게임의 정체성은 카메라 모드임을 명확히.
- 카메라 프리뷰는 실루엣/랜드마크만 표시(실제 영상 미표시 옵션 기본 ON — 프라이버시 부담 완화). 영상은 절대 저장/전송하지 않으며 이를 설정 화면에 명시.

## 13. Art / Sound / Haptic Direction

- **아트**: 미니멀 다크 판타지 + 네온 오컬트. 어두운 배경 + 발광하는 기하학 인장/마법 이펙트. 적은 실루엣 + 림라이트. 이 스타일은 적은 에셋으로 높은 완성도를 내며 파티클/셰이더가 비주얼의 주역이 된다. 개발 중 AI 생성/플레이스홀더 에셋 허용, 단 팔레트(배경 #0B0E14 계열, 마법색은 계열별 네온 1색씩)와 셰이프 언어를 ART_DIRECTION.md로 고정해 일관성 유지.
- **사운드**: 인장 확정음은 계열별로 구분되는 짧은 신스톤. 인장문 완성 시 화음 상승. BGM은 다크 앰비언트 + 전투 시 레이어 추가(수직 레이어링). 무료/CC 에셋 + 필요시 웹오디오 신스.
- **햅틱**: Capacitor Haptics로 인장 확정(가벼움), 인장문 완성(강함), 피격(중간), 보스 기믹 파훼(패턴). 설정에서 끄기 가능.
- **타격감 체크리스트**(각 전투 기능의 완료 조건에 포함): 히트스톱(30~60ms), 화면 흔들림, 피격 플래시, 대미지 숫자, 사망 파티클, 넉백.

## 14. 기술 스택 및 아키텍처

**확정 스택:**
- 게임: **Phaser 3 + TypeScript + Vite**
- CV: **MediaPipe Tasks Vision — Hand Landmarker** (`@mediapipe/tasks-vision`, WASM + WebGL delegate, 브라우저 실행)
- 모바일 패키징: **Capacitor** (Android 우선, iOS는 동일 코드로 후속)
- 테스트: **vitest** (+ 녹화된 랜드마크 fixture)
- 저장: Capacitor Preferences(네이티브) / localStorage(웹) 추상화
- 상태/데이터: 순수 TS 모듈 + JSON 데이터 파일. 외부 상태관리 라이브러리 불필요.

**개발 환경 원칙**: 개발·테스트의 기본 무대는 **데스크톱 브라우저 + 웹캠**이다. Android 실기기는 Phase 0 검증과 각 Phase 종료 시 성능 확인에 사용한다.

**모듈 아키텍처 (결합 최소화가 목표):**

```
[CameraSource] → [HandTracker(MediaPipe)] → [LandmarkFrame]
      → [GestureClassifier] → [TemporalFilter/FSM] → [GestureEvent]
      → [PhraseMatcher(토큰 버퍼)] → [CastEvent]
      → [SpellResolver] → [CombatEvent] → [EventBus] → 게임 시스템들(룬 훅, VFX, 사운드, 통계)
```

핵심 규칙:
- **CV 파이프라인은 Phaser를 전혀 모른다.** `GestureSource` 인터페이스(이벤트 스트림)만 노출한다. 구현체: `CameraGestureSource`(실기), `ReplayGestureSource`(녹화 재생, 테스트용), `ButtonGestureSource`(보조 입력/디버그).
- **전투 로직은 렌더링을 모른다.** 순수 TS로 작성하여 headless 테스트 가능하게.
- 시스템 간 통신은 타입이 정의된 **EventBus** 하나로. (`onSpellCast`, `onSpellHit`, `onEnemyDeath`, `onStatusApplied`, `onWardBlock`, `onGestureRecognized`, `onPhraseCompleted` 등)
- 룬은 EventBus 이벤트에 훅을 거는 순수 데이터 + 소수의 Action 실행기.

**디렉토리 구조:**

```

├── src/
│   ├── cv/               # 카메라, MediaPipe 래퍼, 정규화 (Phaser 무관)
```

## 15. Gesture Recognition Pipeline (구현 사양)

**전처리/정규화:**
1. Hand Landmarker에서 21개 랜드마크 + handedness 취득.
2. 손목(landmark 0)을 원점으로 평행이동, `|손목→중지 MCP(9)|` 거리로 스케일 정규화.
3. handedness가 Left면 x축 미러 → 좌우 손 동일 코드 경로.

**특징 추출:**
- 손가락별 굽힘도 5개: 각 손가락 (MCP→PIP→TIP) 관절 각도에서 산출한 0~1 값.
- 핀치 거리: 엄지 끝(4)–검지 끝(8) 정규화 거리.
- V 판별 보조: 검지 끝(8)–중지 끝(12) 거리.

**분류 — 1차는 규칙 기반 (ML 분류기 금지, 필요성이 증명되기 전까지):**
- Fist: 5손가락 모두 굽힘 > 0.7
- Palm: 5손가락 모두 굽힘 < 0.25
- Point: 검지 < 0.25, 나머지 > 0.6
- V: 검지·중지 < 0.25, 약지·소지 > 0.6, 검지–중지 끝 거리 > 임계값
- Pinch: 핀치 거리 < 임계값, 중지·약지·소지 자유
- 어느 것에도 확실히 속하지 않으면 `NONE`. confidence = 규칙 마진으로 산출.

**Temporal Filter / FSM:**
- 같은 후보 인장이 **연속 N프레임(기본 4)** confidence ≥ 임계값으로 유지되면 확정 → `GestureEvent` 발화 → 같은 인장 재발화까지 최소 300ms 디바운스, 해제는 히스테리시스(낮은 임계값)로.
- 확정 즉시 스펠 발동 + PhraseMatcher 토큰 버퍼에 push (§6 규칙).
- 손 미검출 1초 지속 시 "손을 보여주세요" UI 상태.

**성능 전략 (CV):**
- 추론은 렌더 루프와 분리. 목표 추론 15~24fps (`requestVideoFrameCallback` 또는 자체 스로틀), 렌더는 60fps 유지.
- 입력 해상도 다운스케일(짧은 변 ~256px). 가능하면 Web Worker + OffscreenCanvas로 메인 스레드 부하 격리 — Phase 0에서 워커 실행 가능 여부를 검증하고 불가하면 메인 스레드 + 스로틀로.
- 웨이브 사이 휴지 구간에는 추론 fps를 낮춰 발열/배터리 절약.
- 매 프레임 배열/객체 재할당 금지(특징 버퍼 재사용), GC 스파이크 방지.

## 16. 너(AI)의 작업 방식과 자율성

**작업 사이클 (모든 작업 단위마다):**
Analyze(관련 코드 먼저 읽기) → Plan → Implement(작은 단위) → Build(`npm run build` 또는 dev 확인) → Test(`npm test`) → Inspect → Fix → Refactor → Commit-ready 상태로 마무리.

**지켜야 할 규칙:**
- 기존 구현을 무시하고 재작성하지 않는다. 한 번에 프로젝트 전체를 수정하지 않는다.
- 임시 우회 코드·`TODO`만 남기고 넘어가지 않는다. 오류는 원인 분석 후 수정.
- 명확한 네이밍, 단일 책임, 상속보다 컴포지션, 불필요한 싱글턴·전역 상태 금지, 매직 넘버는 데이터/상수로.
- 콘텐츠(스펠/룬/적/인장문/스테이지)는 코드가 아니라 `data/` JSON으로. 로직과 데이터 분리.
- 지나친 추상화 금지. 세 번째 중복이 생기기 전엔 일반화하지 않는다.
- **Git / GitHub 워크플로우 (자동 수행, 승인 불필요):**
  - 리포지토리는 GitHub 원격(origin)에 연결한다. 원격이 없으면 사용자에게 리포 URL을 한 번만 확인한다.
  - 작업 단위마다 브랜치 생성: `feat/...`, `fix/...`, `phase0/...` 등. 하나의 논리 변경 = 하나의 브랜치.
  - 작업 단위 완료(빌드·테스트 통과) 시 **자동으로**: 커밋 → `main`으로 `git merge --no-ff`(머지 커밋 생성) → `git push origin main`. 매번 사용자에게 묻지 않는다.
  - 머지 히스토리를 유지한다: `main`은 항상 머지 커밋으로 성장. `main`에 force-push 금지. 충돌 시 브랜치를 `main` 위로 리베이스한 뒤 다시 머지.
  - **폴백**: 브랜치/머지/푸시가 실패하는 환경(권한, 인증, 충돌 반복 등)이면 우회 시도에 시간을 낭비하지 말고 `main`에 직접 커밋 + 푸시로 전환하고, 전환 사실과 이유를 한 줄 보고한다. 푸시 자체가 불가하면 로컬 커밋만 쌓고 보고한다.
  - 커밋 메시지: `feat: ...` / `fix: ...` / `refactor: ...` conventional 스타일, 본문에 변경 요지 1~3줄.
  - Phase 종료 시 `phase-N` 태그를 남긴다.
- 로그: 경량 로거(`core/log.ts`)로 카테고리별(cv/gesture/combat) 로그. 릴리스 빌드에서 자동 무음.

**자율성:**
- 이 문서의 세부 수치(임계값, 밸런스, 인장문 구성 등)는 초기값이다. 더 나은 판단이 있으면 변경하라. 단: 변경 이유를 `docs/DECISIONS.md`에 기록하고, 복잡도 대비 효과를 판단하며, "제스처가 게임의 전부"라는 정체성과 출시 가능성을 해치지 않아야 한다.
- 사소한 것을 사용자에게 계속 묻지 마라. 정보가 부족하면 합리적 기본값으로 진행하고 기록하라. 아키텍처 급 변경만 사용자에게 명시적으로 보고한다.

**하지 말 것 (스코프 가드):**
온라인 멀티플레이, 서버, 계정, 가챠, PvP, 길드, 오픈월드, 수백 스테이지, 방대한 스토리, 커스텀 제스처 등록(Release 이후 검토), ML 학습 파이프라인(규칙 기반이 한계를 보이기 전까지), 사용자 영상 저장/전송(영구 금지).

## 17. Debug / Testing / Analytics

**디버그 (개발 빌드 전용, `?debug=1` 또는 토글, 실제 게임 UI와 분리):**
- Gesture Simulator: 키보드 1~5로 인장 강제 발화(ButtonGestureSource 재사용).
- 랜드마크/특징값/confidence 실시간 시각화 오버레이.
- 스펠 강제 발동, 룬 강제 획득, 무적, 배속(x2/x4), 특정 방 이동, 적 스폰 명령.
- 성능 HUD: 렌더 FPS, CV 추론 시간(ms), 추론 fps, 엔티티 수, (가능하면) 메모리.
- **랜드마크 레코더**: 현재 카메라 입력의 랜드마크 스트림을 JSON으로 녹화 → `fixtures/`에 저장.

**테스트 전략:**
- `GestureClassifier` + `TemporalFilter`: 녹화 fixture(각 인장별 정상/경계/노이즈 케이스)를 `ReplayGestureSource`로 재생하여 카메라 없이 vitest로 검증. 각 인장의 인식 성공률과 오인식률을 리포트하는 테스트 스크립트 포함.
- `PhraseMatcher`: 토큰 시퀀스 단위 순수 유닛 테스트(타임아웃, 부분 일치, 리셋).
- `combat/`: 룬 훅 상호작용(화상→폭발→연쇄 등 시너지 체인)을 headless 시뮬레이션으로 검증. 시드 고정 난수 사용.
- 데이터 파일: 로드 시 zod 검증 + 전체 데이터 무결성 테스트(존재하지 않는 spellId 참조 등).

**분석(로컬 전용, 외부 전송 없음):**
런 종료 시 로컬 통계 기록 — 런 시간, 사망 원인, 인장별 사용 횟수·인식 실패율, 인장문 성공률, 스펠별 딜 기여. 디버그 화면에서 열람. 구조는 추후 외부 analytics로 확장 가능하게 인터페이스만 분리.

## 18. Save System

- `SaveData`에 `schemaVersion` 필수. 로드 시 버전별 마이그레이션 함수 체인.
- 저장 항목: 설정(오디오/햅틱/접근성), 제스처 캘리브레이션 보정치, 메타 진행(파편, 해금 목록), 통계, 최고 기록, 업적.

## 19. Android / iOS 빌드 전략

- Capacitor Android: 카메라 권한(`CAMERA`) 및 WebView getUserMedia 허용 설정, 화면 꺼짐 방지(KeepAwake), 세로 고정, 타깃 SDK 최신 유지.

## 20. 개발 로드맵 (Phase별 완료 조건 포함)

> 각 Phase는 Exit Criteria를 전부 만족해야 종료된다. 종료 시 사용자에게 데모 방법(실행 명령/조작법)을 요약 보고한다.

### Phase 0 — Technical Spike (최우선, 게임 코드 작성 금지)
- **Objective**: 프로젝트 최대 리스크인 "브라우저/모바일 실시간 손 추적 + 5종 인장 분류"를 최소 코드로 검증.
- **Tasks**: Vite+TS 스켈레톤 / getUserMedia 전면 카메라 / Hand Landmarker 구동 / 랜드마크 캔버스 표시 / §15 규칙 기반 5종 분류 + confidence 표시 / 추론 시간·확정 지연 측정 HUD / Capacitor로 Android 실기기 실행.
- **Deliverables**: 데스크톱과 Android에서 도는 스파이크 앱, 측정 결과를 담은 `docs/SPIKE_REPORT.md`.
- **Exit Criteria**: 데스크톱에서 5종 인장 각각 20회 시도 중 18회 이상 정인식 / Android 실기기에서 추론 ≥15fps, 인장 확정 지연(포즈 완성→이벤트) ≤400ms, 렌더 60fps 유지 / 오인식(의도와 다른 인장 확정) ≤10%.
- **실패 시 폴백**: Web Worker 이전, 해상도·모델(lite) 조정 → 그래도 실패하면 사용자에게 보고 후 react-native-mediapipe(네이티브 추론) 전환을 논의. 게임 로직은 순수 TS이므로 이식 가능하게 유지한다.

### Phase 1 — Project Skeleton
- **Objective**: 본 프로젝트 구조 확립.
- **Tasks**: §14 디렉토리 구조 / EventBus / 시드 난수 / 로거 / zod 데이터 로더 / Phaser 씬 골격(Boot→Menu→Game→Result) / vitest 셋업 / ARCHITECTURE.md 작성 / Phase 0 코드를 `cv/`, `gesture/`로 정리 이관.
- **Exit Criteria**: `npm run dev`로 씬 전환되는 빈 게임 실행, `npm test` 통과(EventBus·데이터 로더 테스트 포함), lint 클린.

### Phase 2 — Gesture Pipeline 완성
- **Objective**: 게임에서 쓸 수 있는 견고한 제스처 입력.
- **Tasks**: TemporalFilter/FSM/디바운스/히스테리시스 / GestureSource 3구현체(Camera/Replay/Button) / 랜드마크 레코더 + fixture 5세트 이상 녹화 / 인식 피드백 UI(실루엣·게이지) 1차 / 분류기 자동 테스트.
- **Exit Criteria**: fixture 기반 테스트에서 인장별 정인식 ≥90%·오인식 ≤5% / 실기기에서 연속 2분 사용 시 의도치 않은 발화 체감상 드묾 / 카메라 없이 Replay로 전체 파이프라인 테스트 가능.

### Phase 3 — Spell Prototype + 기본 전투 (MVP)
- **Objective**: "손으로 쏘는 게 재밌는가" 검증.
- **Tasks**: 전투 엔티티(플레이어 고정, Crawler 1종) / Bolt·Ward·Pulse 3종 발동 / 피격·사망·재시작 / 오브젝트 풀 / 최소 타격감(히트스톱·흔들림·사운드 3개).
- **Exit Criteria**: 실기기에서 3분 생존 플레이가 성립하고, 개발자 본인이 "버튼보다 제스처가 재밌다"고 판단(아니라면 원인 분석 후 §6 규칙 조정을 먼저 시도).

### Phase 4 — Combat 확장 + Phrase + 룬 시스템
- **Objective**: 시스템적 깊이의 뼈대.
- **Tasks**: Arc·Focus / 마나 / 인장문 3종(PhraseMatcher) / 적 3종 + 텔레그래프 / 상태이상(화상·감전) / 룬 훅 실행기 + 룬 8종(각 계열 포함) / 룬 3택1 UI / headless 시너지 테스트.
- **Exit Criteria**: 데이터 파일만 추가해 새 룬이 동작함을 시연 / 시너지 체인 자동 테스트 통과 / 실기기 60fps 유지.

### Phase 5 — Vertical Slice ★
- **Objective**: **완성된 게임처럼 느껴지는 10~15분 경험 1회분.**
- **Tasks**: 방 8개 런 구조 + 보상/이벤트 방 / 보스(침묵의 서기관, 인장문 기믹 포함) / 룬 12종 / 튜토리얼 + 캘리브레이션 / 메뉴·결과 화면 / 폴리싱 체크리스트(§13) 전 항목 / BGM 1 + SFX 세트 / 햅틱 / 사망·클리어 → 재시작 루프 / 저장(설정·캘리브레이션·최고기록).
- **Exit Criteria**: 처음 보는 사람이 설명 없이(튜토리얼만으로) 1런 완주 가능 / 개발자 기준 "영상 찍어 올리고 싶은 상태" / 15분 연속 플레이 발열 체크 통과 / 알려진 크래시 0.
- **이 Phase 종료 시 반드시 사용자와 함께 플레이테스트 리뷰를 진행하고 다음 단계 우선순위를 재조정한다.**

### Phase 6 — Alpha (콘텐츠 확장)
챕터 2 / 적 8종+ / 엘리트 / 룬 20종+ / 인장문 6종+ / 메타 진행(파편·복원) / 이벤트 방 다양화 / 로컬 통계. **Exit**: 3런 연속 플레이에도 새 조합 발견의 여지가 있음, 데이터 검증 테스트 전체 통과.

### Phase 7 — Beta (완성도)
챕터 3 + 보스 3 / 룬 30종+ / 인장문 8종+ / 밸런스 패스(로컬 통계 활용) / 접근성 옵션 완성 / 보조 입력 모드 정식화 / 저사양 기기 성능 패스 / 세이브 마이그레이션 테스트 / 업적. **Exit**: 외부 테스터 3인 이상이 튜토리얼만으로 완주, 치명 버그 0, 오인식 관련 불만이 주요 피드백에서 사라짐.

### Phase 8 — Release
스토어 등록 준비: 아이콘/스크린샷/소개 영상 스크립트, 개인정보 처리방침(카메라 영상 미저장 명시), 크래시 최종 점검, 버전 태깅. **최종 출시 기준**: Vertical Slice Exit Criteria가 전체 콘텐츠 범위에서 성립 + 스토어 심사 요건 충족.
